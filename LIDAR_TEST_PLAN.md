# План подключения и тестового запуска лидара

Источник: статья на Habr ["Использование лидара от робота-пылесоса для системы предотвращения столкновений в автономных роботах"](https://habr.com/ru/articles/889524/).

Этот файл предназначен для первого автономного запуска лидара по схеме из статьи. Значения пинов впишите вручную под свою плату и свою разводку.

## 1. Цель первого запуска

Минимальная цель теста:

- запитать лидар и `ESP32`;
- принять UART-пакеты лидара на `ESP32`;
- распарсить 8 точек из пакета;
- разбить обзор на 12 секторов;
- увидеть индикацию по секторам в `Serial Monitor`;
- при наличии светодиодного кольца проверить цветовую индикацию.

На первом этапе `Arduino Uno` не обязателен. Его можно подключить позже, когда лидар уже стабильно читается на `ESP32`.

## 2. Что нужно для теста

- лидар от робота-пылесоса с UART-выходом `TX`, питанием `5V` и `GND`;
- плата `ESP32`;
- при желании кольцо `WS2812B / NeoPixel` на 12 светодиодов;
- провода;
- USB-кабель для прошивки и просмотра лога;
- стабильное питание.

Опционально для второго этапа:

- `Arduino Uno` как приемник строки `SECTORS: ...` от `ESP32`.

## 3. Логика подключения

Базовая идея из статьи:

- лидар передает данные по `UART` в `ESP32`;
- `ESP32` считает расстояния по секторам;
- `ESP32` показывает состояние на светодиодном кольце;
- `ESP32` может дополнительно отправлять упрощенные статусы в `Arduino Uno`.

## 4. Таблица подключения

Заполните пины вручную перед прошивкой.

### Лидар -> ESP32

- `Lidar 5V` -> `ESP32/внешнее питание 5V: <вписать>`
- `Lidar GND` -> `ESP32 GND: <вписать>`
- `Lidar TX` -> `ESP32 RX (Serial1): <вписать>`
- `Lidar RX` -> `ESP32 TX (Serial1): <вписать, если нужен>`

Примечание:

- во многих случаях для чтения достаточно только линии `TX` от лидара в `RX` контроллера;
- если обратная линия не используется, ее можно не подключать;
- земля `GND` у всех устройств должна быть общей.

### Светодиодное кольцо -> ESP32

- `NeoPixel DIN` -> `ESP32 GPIO: <вписать>`
- `NeoPixel 5V` -> `5V: <вписать>`
- `NeoPixel GND` -> `GND: <вписать>`

### ESP32 -> Arduino Uno, если нужен второй этап

- `ESP32 TX2` -> `Arduino RX: <вписать>`
- `ESP32 RX2` -> `Arduino TX: <вписать, если нужен обратный канал>`
- `ESP32 GND` -> `Arduino GND`

## 5. Что проверить до включения питания

- лидар действительно рассчитан на `5V`, а не на `3.3V`;
- `TX` устройства идет в `RX` принимающей стороны;
- все устройства имеют общую землю;
- USB-питания хватает для теста;
- если используете кольцо `WS2812B`, питание не просаживается при включении.

## 6. Какие параметры должны быть в прошивке ESP32

В коде из статьи нужно вручную заполнить или проверить:

- `LIDAR_RX_PIN`
- `LIDAR_TX_PIN`
- `UART_TX_PIN`
- `UART_RX_PIN`
- `LED_PIN`
- `BAUDRATE = 115200`
- `NUM_SECTORS = 12`
- `ALARM_DIST = 400`
- `WARNING_DIST = 650`
- `ALARM_HOLD_MS = 300`
- `SECTOR_OFFSET = 1`

Если на первом запуске хотите максимально простой тест, можно оставить только:

- чтение лидара;
- вывод строки `SECTORS: ...` в `Serial`;
- отключить второй микроконтроллер;
- при необходимости временно не использовать кольцо светодиодов.

## 7. Рекомендуемый порядок первого запуска

### Этап 1. Проверка только ESP32 и лидара

1. Подключить только `ESP32` и лидар.
2. Не подключать пока `Arduino Uno`, чтобы исключить лишние источники ошибок.
3. Открыть код из статьи и вручную прописать свои пины.
4. Прошить `ESP32`.
5. Открыть `Serial Monitor` на скорости `115200`.
6. Подать питание на лидар.
7. Проверить, что в логе появляется строка старта:
   - `ESP32 Lidar parser.`
8. Проверить, что дальше регулярно появляются строки вида:
   - `SECTORS: 0 0 1 2 0 0 0 0 0 0 0 0`

Ожидаемая интерпретация статусов:

- `0` -> сектор безопасен, зеленый;
- `1` -> сектор в зоне предупреждения, желтый;
- `2` -> сектор в опасной зоне, красный.

### Этап 2. Проверка реакции на препятствие

1. Поставить перед лидаром объект на разном расстоянии.
2. Медленно перемещать объект между секторами.
3. Следить за логом `SECTORS: ...`.
4. Если подключено кольцо `WS2812B`, убедиться:
   - дальняя зона дает зеленый;
   - средняя зона дает желтый;
   - ближняя зона дает красный.

Ожидаемое поведение по порогам из статьи:

- меньше `400 мм` -> красный;
- от `400 мм` до `650 мм` -> желтый;
- больше `650 мм` -> зеленый.

### Этап 3. Подстройка ориентации секторов

1. Поставить один заметный объект в фиксированное место относительно "переда" робота.
2. Посмотреть, какой сектор срабатывает.
3. Подправить `SECTOR_OFFSET`, если индикация повернута относительно реального направления.
4. Повторять, пока "нулевой" сектор не будет совпадать с нужным направлением.

### Этап 4. Подключение Arduino Uno, если нужно

1. Подключить `UART2` от `ESP32` к `Arduino Uno`.
2. Залить приемный скетч из статьи.
3. Открыть `Serial Monitor` у `Arduino Uno`.
4. Проверить, что `Arduino` принимает строку и печатает:
   - `Sectors received: ...`

## 8. Минимальные критерии успешного теста

Считаем первый запуск успешным, если:

- `ESP32` стабильно стартует;
- лидар выдает повторяющиеся данные без зависаний;
- в `Serial Monitor` идут строки `SECTORS: ...`;
- сектор меняет состояние при приближении объекта;
- после настройки `SECTOR_OFFSET` направление совпадает с физическим расположением лидара.

## 9. Если данных нет

Проверять в таком порядке:

1. Есть ли у лидара стабильное питание `5V`.
2. Совпадает ли скорость `UART`: `115200`.
3. Верно ли подключен `TX` лидара в `RX` `ESP32`.
4. Есть ли общая земля между устройствами.
5. Правильно ли указаны пины в прошивке.
6. Не мешает ли второй подключенный контроллер, если он уже добавлен в схему.
7. Не слишком ли высокий порог фильтра по интенсивности `intensities[i] > 15`.

## 10. Что лучше не делать на первом тесте

- не подключать сразу и лидар, и кольцо, и `Arduino Uno`, и моторы;
- не смешивать первый тест лидара с запуском `ROS2`;
- не пытаться одновременно отлаживать питание, UART и логику секторов.

Сначала нужно добиться простого стабильного вывода `SECTORS: ...` в `ESP32`, и только потом переходить к остальной системе.

## 11. Следующий шаг после успешного теста

После автономной проверки можно переходить к одному из двух сценариев:

- оставить `ESP32` как отдельный модуль предотвращения столкновений;
- передавать данные дальше в `Arduino` или в более высокоуровневую систему робота.
