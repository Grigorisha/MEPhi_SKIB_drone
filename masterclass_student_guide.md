# ROS2 мастер-класс — шпаргалка для тебя

Сегодня подвигаешь виртуальную черепашку, потом — настоящего робота. Просто копируй команды по порядку.

Три главных слова, которые встретятся:
- **Нода** — отдельная запущенная программа.
- **Топик** — "канал", в который одни ноды пишут сообщения, а другие читают.
- **Сообщение** — то, что летит по топику (например, команда скорости).

---

## Часть 1. Разминка в симуляторе

Открой **два терминала**.

**Терминал 1** — запускаем черепашку:
```bash
source /opt/ros/humble/setup.bash
ros2 run turtlesim turtlesim_node
```

**Терминал 2** — рулим ей стрелками на клавиатуре:
```bash
source /opt/ros/humble/setup.bash
ros2 run turtlesim turtle_teleop_key
```
(Кликни именно во второй терминал, чтобы стрелки ловились им, а не окном черепашки.)

**Посмотреть, что происходит внутри** (третий терминал, пока черепашка ещё бегает):
```bash
source /opt/ros/humble/setup.bash
ros2 node list                 # какие ноды сейчас запущены
ros2 topic list                # какие топики существуют
ros2 topic echo /turtle1/cmd_vel   # смотрим сообщения вживую (жми стрелку во 2 терминале)
```

**Если успел раньше других** — попробуй подвигать черепашку без клавиатуры, напрямую командой:
```bash
ros2 topic pub /turtle1/cmd_vel geometry_msgs/msg/Twist "{linear: {x: 2.0}, angular: {z: 1.0}}" --once
```

## Часть 2. Подключаемся к настоящему роботу

```bash
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=42

ros2 topic list
```
Должны появиться темы робота: `/cmd_vel`, `/joint_states`, `/scan`, `/tf` и другие.

**Пусто?** Проверь:
1. Правильно ли ввёл `export ROS_DOMAIN_ID=42` (без него ничего не увидишь).
2. Подключён ли к той же Wi-Fi сети, что и робот.
3. Спроси преподавателя — возможно, на роботе ещё не запущен bringup.

**Посмотреть живые данные с настоящего робота:**
```bash
ros2 topic hz /joint_states     # частота обновления (~50 Гц — робот "жив")
ros2 topic echo /joint_states --once
```

## Часть 3. Твоя очередь порулить

Когда подойдёт очередь — садись за место водителя и вводи:
```bash
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=42
ros2 run teleop_twist_keyboard teleop_twist_keyboard
```

Управление:

| Клавиша | Действие |
|---|---|
| `i` | вперёд |
| `,` | назад |
| `j` | разворот на месте влево |
| `l` | разворот на месте вправо |
| `k` | стоп |

**Задание:** доехать от точки А до точки Б, не задев препятствия.

**Важно:** закончил — обязательно нажми `k`, потом `Ctrl+C`, только после этого следующий человек запускает свой teleop. Если два teleop работают одновременно, робот получает противоречивые команды.

## Бонус — посмотреть глазами робота (лидар)

Если преподаватель скажет, что лидар работает:
```bash
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=42
rviz2
```
В открывшемся окне: **Add** (внизу слева) → вкладка **By topic** → найти `/scan` → **LaserScan** → Add.
Наверху слева, в Global Options, поле **Fixed Frame** поставить `base_link`.

Теперь видно, как робот "видит" комнату лучом лидара в реальном времени.

---

## Если что-то не работает

| Проблема | Что делать |
|---|---|
| `ros2 topic list` ничего не показывает | Проверь `export ROS_DOMAIN_ID=42` — без него твой компьютер и робот "на разных радиоканалах" |
| Робот не реагирует на нажатия | Убедись, что окно терминала с teleop активно (кликни в него), и что больше никто не запустил свой teleop одновременно |
| Всё равно не работает | Позови преподавателя, не трогай сам провода/робота |
